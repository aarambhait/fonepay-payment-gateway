Vendor documents are written by busy people, and Fonepay's are no exception. This page lists places where the source documents **contradict themselves or are silent**, how these guides handled each, and what to ask Fonepay.

Sources: Dynamic QR "Merchant Integration through Device for online QR" and Checkout Intent Flow **v1.10 (20 May 2026)**.

:::tip[Found a new one, or got an answer from Fonepay?]
Please [open an issue or pull request](../../about/contributing/) so everyone benefits.
:::

## Dynamic QR

| # | Issue | What these docs do | Ask Fonepay |
|---|---|---|---|
| 1 | The **live** API URL appears both **with** and **without** `/convergent-merchant-web/` | Shows the version without, as in the endpoint section | What is the exact production URL? |
| 2 | The Java sample prints **uppercase** hex (`0123456789ABCDEF`), but the sample signature is **lowercase** | Uses lowercase | Is `dataValidation` case-insensitive? |
| 3 | Live WebSocket URL is only given as `wss://ws.fonepay.com/` in one note | Uses the full path shown in the endpoint section, and tells you to use the URL from the response | Confirm the production WebSocket host |
| 4 | The tax refund section's parameter table is titled "QR Request Parameters" | Treats it as the tax refund request | None |
| 5 | Credentials (`username`, `password`) travel in **every request body** | Strongly recommends server-side calls only | Is there a token-based alternative? |
| 6 | The WebSocket is described as "between server and browser", but no authentication for the socket is described | Treats events as hints and verifies via status API | Is the socket URL a secret? Does it expire? |
| 7 | Response strings contain typos (`successfull`, `Sucess`) | Tells you not to match on message text | None |
| 8 | The status API does not return the paid amount | Recommends storing the amount per `prn` | Can the amount be added? |

## Not covered by the documents we have

- Rate limits and timeouts
- QR and session expiry times
- Refunds and reversals through the API
- Settlement and reconciliation reports
- Production go-live and certification steps
- Webhook-style callbacks (beyond WebSocket)

Ask Fonepay or your bank about each of these before you go live.
