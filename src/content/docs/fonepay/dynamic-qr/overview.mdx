Dynamic QR generates a **unique QR code for each payment**. The customer scans it with any participating banking app, approves the payment, and Fonepay tells you the result.

## Flow

```text
Merchant server                              Fonepay
      |  1. POST thirdPartyDynamicQrDownload     |
      |----------------------------------------->|
      |  2. qrMessage + WebSocket URL            |
      |<-----------------------------------------|
      |  3. Open WebSocket, show the QR          |
      |<=========================================|
      |  4. "VERIFIED" (customer scanned)        |
      |  5. payment result (paymentSuccess)      |
      |  6. POST thirdPartyDynamicQrGetStatus    |
      |----------------------------------------->|
      |  7. paymentStatus: success/failed/pending|
      |<-----------------------------------------|
```

1. [Generate the QR](../generate-qr/) from your server.
2. Render `qrMessage` as a QR image and open the [WebSocket](../websocket/).
3. When a message arrives, [check the status](../check-status/) from your server.
4. Optionally, [report tax details](../tax-refund/) to Fonepay for IRD.

## Endpoints

All are `POST` requests with a JSON body, relative to the API base.

| Purpose | Path |
|---|---|
| Generate a QR | `/thirdPartyDynamicQrDownload` |
| Check payment status | `/thirdPartyDynamicQrGetStatus` |
| Post tax refund details | `/thirdPartyPostTaxRefund` |

Every request carries your `merchantCode`, `username`, `password` and a `dataValidation` signature. Read [Authentication](../authentication/) next.
